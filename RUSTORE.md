# Публикация в RuStore

Порядок действий от нуля до карточки в магазине.

## 1. Создайте ключи подписи

```
bash tools/make-keystore.sh
```

RuStore подписывает приложения сам, как Google Play, поэтому ключей **два**,
и скрипт создаёт оба в одном `release.keystore`:

| Алиас | Что делает | Кто им владеет |
|---|---|---|
| `sign_v1` | Им RuStore подписывает APK, которые получают пользователи | отдаётся RuStore в зашифрованном виде |
| `upload` | Им подписывается `.aab`, который вы загружаете | остаётся только у вас |

Скрипт напечатает значения для секретов GitHub — обратите внимание, что
`KEY_ALIAS` здесь `upload`, а не `sign_v1`: сборка подписывает загрузку.

> Сохраните `release.keystore` и пароль. Потерянный `upload` RuStore может
> сбросить через поддержку, потерянный `sign_v1` до его передачи в RuStore —
> нет.

## 2. Отдайте подпись RuStore

В консоли откройте раздел **Подпись приложения**. Там будет токен шифрования
и ссылка на `pepk.jar` — оба свои для каждого приложения. Скачайте `pepk.jar`
и выполните:

```
bash tools/prepare-rustore-signing.sh release.keystore <токен> pepk.jar
```

Получатся два файла для двух полей формы:

- `pepk_out.zip` — ключ подписи приложения (`sign_v1`)
- `uploadcert.pem` — сертификат ключа загрузки (`upload`)

Загрузка `.aab` разблокируется только после того, как RuStore их проверит,
так что этот шаг идёт до сборки, а не после.

## 3. Добавьте секреты в репозиторий

**Settings → Secrets and variables → Actions → New repository secret**

| Секрет | Значение |
|---|---|
| `KEYSTORE_BASE64` | длинная строка, которую напечатал скрипт |
| `KEY_ALIAS` | `upload` |
| `KEYSTORE_PASSWORD` | ваш пароль |
| `KEY_PASSWORD` | тот же пароль |

Без них сборка намеренно падает с объяснением: неподписанный файл RuStore
всё равно отклонит, и лучше узнать об этом сразу, а не после загрузки.

## 4. Соберите

Залейте проект в репозиторий и откройте вкладку **Actions** — сборка
запустится сама. Через 3–5 минут в завершившемся запуске будет артефакт
`knights-tour-rustore`, внутри:

- `app-release.aab` — **его и загружайте в RuStore**
- `app-release.apk` — для проверки на своём телефоне перед отправкой

В логе шага «Show version and signature» виден отпечаток сертификата.
Он должен совпадать у всех будущих сборок.

## 5. Проверьте APK на телефоне

Установите `app-release.apk` и убедитесь, что всё работает. После публикации
исправлять будет дольше: каждая правка — новая модерация.

## 6. Заполните карточку

Все тексты и картинки лежат в `rustore-assets/`:

| Поле карточки | Откуда взять |
|---|---|
| Название, описания | `listing-ru.md` |
| Иконка 512×512 | `icon-512.png` |
| Скриншоты | `screenshot-1.png` … `screenshot-6.png` |
| Политика конфиденциальности | залейте `privacy-policy.html` на GitHub Pages |
| Возрастной рейтинг | ответы на анкету — в `listing-ru.md` |

Политику положите в репозиторий `knights-tour`, чтобы она открывалась по
адресу вида `https://<логин>.github.io/knights-tour/privacy-policy.html`.
Страница должна открываться без входа в аккаунт.

## 7. Отправьте на модерацию

Проверка занимает от одного до пяти рабочих дней.

## Выпуск обновления

1. Поднимите версию в `app/build.gradle`:
   ```
   versionCode 161      // строго больше предыдущего
   versionName "1.1.1"
   ```
   `versionCode` обязан расти, иначе RuStore откажет в загрузке.
2. Залейте изменения — Actions соберёт новый `.aab`.
3. Загрузите его как новую версию в консоли RuStore.

## Требования, которым сборка уже соответствует

| Требование RuStore | Статус |
|---|---|
| targetSdk не ниже 28 | 34 |
| Подписанный артефакт | подпись v1 + v2, сборка без ключа запрещена |
| 64-битные библиотеки | нативного кода нет, требование не применяется |
| Формат AAB или APK | собираются оба |
| Имя пакета неизменно после публикации | `io.github.knightstour` — **поменять можно только сейчас** |

Имя пакета задаётся в `app/build.gradle` (`applicationId` и `namespace`).
После первой публикации оно фиксируется навсегда, так что если хочется
другое — меняйте до отправки.
